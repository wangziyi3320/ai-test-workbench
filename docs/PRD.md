# TraceLab 产品需求与验收标准

版本：0.1.0（个人作品集演示）
目标用户：测试工程师、AI 应用开发者、小团队产品/项目负责人。

## 问题与目标

测试点常分散在需求文档、个人笔记和缺陷表中；用例生成工具又容易把未经核对的内容当成已确认结果。TraceLab 把“来源需求 → 生成草稿 → 人工审核 → 本机 GET 执行或导出 → 缺陷”放在同一个本地工作台，并保留来源字段。

本版内置执行器只覆盖本机、无请求体 GET 的状态码断言。复杂接口仍需导出 Postman Collection，由测试人员补全参数、请求体与鉴权。

## 用户故事

1. 作为测试人员，我可以粘贴文字需求或上传 TXT/Markdown/OpenAPI JSON，在本地保存原文，以便回看。
2. 我可以在离线规则和真实模型 API 两种生成模式间选择，生成带来源定位的测试用例草稿。
3. 我可以逐条修改步骤、预期、优先级和审核状态。只有审核通过的用例可以导出。
4. 我可以导出 CSV；对于接口用例，可以导出带 HTTP 状态码断言的 Postman Collection 草稿。
5. 我可以对已审核且具备 HTTP 方法、路径和预期状态码的本机 GET 用例执行检查，查看实际状态与耗时。
6. 我可以记录缺陷并关联到该需求下的某条用例，更新缺陷状态。

## 本版范围

| 模块 | 验收标准 | 验证方式 |
|---|---|---|
| 需求导入 | 支持文字输入及 UTF-8 TXT/MD/OpenAPI JSON；超过 200 KB 的上传拒绝 | API 自动化测试及页面手工操作 |
| 离线生成 | 基于原文分条；识别简单“4 至 12”范围边界；重复生成不重复插入 | 自动化测试 |
| 模型生成 | 配置兼容 Chat Completions 的 API 后可返回结构化草稿；无配置时明确提示 | Mock API 测试，实际密钥由使用者自行配置 |
| 人工审核 | 用例默认待审核；可编辑后通过或弃用 | API 自动化测试及页面手工操作 |
| 用例导出 | CSV 仅包含通过的用例；防止表格软件公式注入 | 自动化测试 |
| Postman 导出 | 仅包含通过且具备方法、路径、预期状态码的接口用例；含状态码断言 | 自动化测试 |
| 本机 GET 执行 | 只允许审核通过的完整用例与本机 HTTP 地址；不跟随重定向；保留状态、耗时和失败原因 | Mock HTTP 自动化测试及浏览器手工操作 |
| 缺陷管理 | 记录标题、严重级别、步骤、预期、实际；关联用例必须属于同一需求 | 自动化测试 |
| 本地保存 | 重启后可读取 SQLite 中的需求、用例、缺陷 | SQLite 持久化实现及页面手工操作 |

## 产品边界

- 文档必须脱敏；本版无账号与团队权限，不应暴露在公网。
- 离线模式是确定性规则生成，不等同于大模型能力；模型生成可能犯错，审核是必经环节。
- 文字需求中未写明的业务结果不会自动推断。边界越界结果会提示人工补充。
- 当前 OpenAPI 只支持 JSON，不展开 `$ref`，不自动填充接口参数、鉴权与请求体；Postman 导出后应由测试人员补全。内置执行器只支持本机 GET 状态码检查，不代表完整接口回归能力。
- 不宣称缺陷发现率、效率提升或模型准确率；这些数据需要真实场景与基线实验。

## 后续迭代候选

优先级根据真实使用反馈调整：OpenAPI `$ref` 解析、带参数和请求体的受控执行、评审历史、权限控制、批量导入 Jira/禅道、模型结果评测数据集。
